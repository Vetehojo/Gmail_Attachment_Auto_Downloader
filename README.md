# Gmail Attachment Downloader

Gmail に届いた添付ファイルを、Windows PC の指定フォルダー（ファイルサーバーや NAS 上の共有フォルダーを含む）へ自動保存する常駐ツール。

確認するのは Gmail の**受信トレイ**（`in:inbox`）にあるメールだけ。確認する前に受信トレイから外れたメール（アーカイブしたメールや、フィルタで受信トレイをスキップしたメールなど）は処理しない。

> **English**: A Windows tray application that automatically downloads Gmail attachments into a local or network folder. Only mail in the Gmail inbox is checked. Read-only Gmail access, durable SQLite queue, Japanese UI. MIT licensed and provided as-is.

## できること

- 一定間隔（既定 60 秒）で受信トレイを確認し、新着メールの添付ファイルを保存先へダウンロードする
- 保存名を「元ファイル名 / 受信日 / 件名 / 送信元」のテンプレートで整形する。受信日は、Gmail がメールを受け取った日時をこの PC のタイムゾーンで表した日付
- 取得状況を SQLite の処理キューに記録する。PC を止めていた場合も、次に起動したときに前回確認した時点の 5 分前から確認を再開するため、その間に届いて受信トレイに残っているメールも対象になる。同じメールの同じ添付は記録で見分け、重ねて保存しないようにしている
- 保存に失敗した添付はタスクトレイのアイコンで知らせ、一覧から内容を確認して再取得できる
- 保存先ごとにアカウントを分けられる（Google Workspace のドメイン全体の委任を使う場合）

## できないこと

- **メール本文中の URL は扱わない。** 添付ファイルだけが対象
- Gmail 以外のメールサービスには対応しない
- 保存先は Windows から見えるフォルダーのみ。クラウドストレージへ API で直接アップロードはしない
- **メールボックスへの書き込みを一切しない。** 送信・削除・既読化・ラベル変更はできない（`gmail.readonly` のみを使う）
- 同じメールボックスを複数の PC で自動取得する使い方には対応しない。処理キューは PC ごとにあるため、同じ添付が PC の台数分保存される

## 複数の PC から同じ共有フォルダーへ保存する場合

- 別々のメールボックスを受け持つ複数の PC が、同じ共有フォルダーへ保存してよい。保存先に同じ名前のファイルがあれば上書きせず、「(1)」などを付けた名前で保存する。ほかの PC が同時に同じ名前で保存したときは、その次の番号から探し直すため、番号が飛ぶことがある
- 共有フォルダーを使う PC は、すべて同じバージョンにそろえる。古いバージョンは、ほかの PC が保存したファイルを上書きしたり、保存途中の一時ファイルを削除したりすることがある

## 動作環境

- Windows 10 / 11
- Python 3.14 専用。3.13 以下・3.15 以上は対応せず、setup.bat が停止する
- Gmail API を有効化した Google Cloud プロジェクト（利用者自身が用意する）

## 導入

### 1. Google 側の準備

自分の Google Cloud プロジェクトを作成し、Gmail API を有効化して、認証方式に応じた JSON を用意する。

| 使い方 | 必要なもの |
| --- | --- |
| 個人 Gmail / 単独アカウント | デスクトップアプリ用の OAuth クライアント JSON |
| Google Workspace の複数アカウント | サービスアカウント JSON ＋ 管理コンソールでのドメイン全体の委任（`gmail.readonly` のみ承認） |

OAuth 同意画面のユーザーの種類が「外部」で、公開ステータスが「テスト」のままだと、リフレッシュトークンが 7 日で失効し、再ログインが必要になる。継続運用するなら公開ステータスを「本番環境」にすること。「テスト」のまま使う場合は、ログインする Gmail アカウントをテストユーザーに追加しておく（追加していないアカウントはログインを拒否される）。未検証のアプリでは同意時に「Google で確認されていません」の警告が出るが、自分のプロジェクトで自分のメールボックスを読む用途ではそのまま進めてよい。

### 2. インストールと設定

```
setup.bat
```

Python 3.14 を確認し、依存パッケージを `requirements.lock` に記載した固定バージョンで導入したあと、設定画面が開く。対象メールアドレス・添付ファイルの保存先・認証用 JSON を指定し、「Googleに接続してテスト」（ドメイン全体の委任では「登録した全アカウントに接続してテスト」）で導通を確認する。テストでは設定も認証情報も書き換えない。「保存」を押したときに、認証情報（OAuth のログイン結果の `token.json` を含む）と設定をまとめて保存する。トレイアプリが動いている間は setup.bat から設定画面を開けないので、トレイメニューの「設定」を使う。

依存パッケージは仮想環境を使わず、PATH 上の Python 3.14 へ入れる。同じ Python を使うほかのプログラムがあると、共通のパッケージ（requests、urllib3、certifi、cryptography、protobuf、Pillow など）の版が上がったり下がったりすることがある。このアプリが依存パッケージの版を変えるのは、新しい版のアプリを入れて setup.bat を実行したときだけである。ほかのプログラムが同じ Python にパッケージを入れると、このアプリが使う版も変わることがある（setup.bat を実行し直すと `requirements.lock` の版に戻る）。新しい版で setup.bat を実行する前に、トレイメニューの「終了（自動取得を停止）」でトレイアプリを終了しておく。

設定を保存すると、お試し取得をするか聞かれる（`[Y/n]`）。お試し取得は、各アカウントの受信トレイから保存対象の添付があるメールを新しい順に 3 件だけ保存する。設定画面の取込期間は使わない。setup.bat は自動取得を開始しない。

### 3. 保存結果の確認

保存先のファイル名と内容を確認する。

お試し取得で保存した添付は、その時点の保存先とファイル名で記録される。あとで保存先やファイル名の設定を変えても、お試し取得をもう一度実行しても、自動取得が始まっても、これらの添付は新しい設定では保存し直されない。必要なら手作業で移動・改名する。トレイメニューの「添付を取り直す」も、最初に記録した保存先へ、現在のファイル名の設定で保存し直すだけである。お試し取得で保存できなかった添付や再試行待ちの添付も、お試し取得の時点の保存先を記録しており、あとで保存するときもその保存先を使う。

認証を済ませたあとや、保存する拡張子を見直したあとなどに、まだ保存していない添付でもう一度試すときは `trial_download.bat` を実行する。トレイアプリが動いているとお試し取得は実行できないので、先にトレイメニューの「終了（自動取得を停止）」で終了しておく。

### 4. 自動取得の開始

```
register_logon_task.bat
```

管理者として実行する必要はない。ふだん使うユーザーのまま実行する（別の管理者アカウントで実行すると、タスクはそのアカウント用に登録される）。実行したユーザーのログオンの 1 分後にトレイアプリを起動するタスクと、5 分ごとに監視プロセスを確認するタスクを登録する。どちらもバッテリー駆動中でも動き、トレイアプリには実行時間の上限がない。登録が終わると、登録したタスクを実行してその場でトレイアプリを起動する。一時停止中や設定が未完了でなければ、そのまま自動取得が始まる。起動できなかった場合は次回ログオン時に起動する。お試し取得で保存した添付は、自動取得でも同じ添付として扱い、保存し直さないようにしている（確認方法は SETUP_GUIDE.md の「お試し取得」を参照）。

Python ファイルをフォルダー直下に置いていた以前の版から更新するときは、先に古いタスクを削除する必要がある（手順は SETUP_GUIDE.md の「旧フォルダー構成からの更新」。古いタスクの削除を拒否されたときは、タスクスケジューラを管理者として実行して削除する）。タスクの詳細は SETUP_GUIDE.md の「タスクの登録」、詳しい手順・仕様は [SETUP_GUIDE.md](SETUP_GUIDE.md) を参照。

## タスクトレイのメニュー

| 項目 | 内容 |
| --- | --- |
| 状態を表示 | 接続方式・状態とその理由・メール確認の状況・添付の処理件数・直近のエラーを確認する |
| 今すぐGmailを確認 | 次の定期確認を待たずに実行する |
| 一時停止 / 再開 | 自動取得を止める・再開する。一時停止はログオンし直しても続く |
| 失敗した添付 | 失敗した添付の内容を確認し、再取得・無視ができる |
| 添付を取り直す | 直近 90 日以内に取得できた添付を、最初に記録した保存先へ、現在のファイル名の設定でもう一度ダウンロードする |
| 期間を指定して再確認 | 指定した日以降のメールを確認し直す |
| 設定 | 設定画面を開く |
| 添付ファイルの保存先を開く | 保存先フォルダーをエクスプローラーで開く |
| 終了（自動取得を停止） | トレイアプリを終了し、自動取得を止める。次回ログオンでトレイアプリが起動すると再開する（一時停止中だった場合は一時停止のまま） |

## 認証情報の扱い

- 指定した JSON と、OAuth 認証後の `token.json` は、設定画面で「保存」を押したときに `%LOCALAPPDATA%\GmailAutoDownloader\` へ保存し、Windows ACL の継承を切って実行ユーザーだけがアクセスできるようにする
- 接続テストで確認したメールボックスを記録し、自動取得は実際に接続したメールボックスが記録と違えば取得を止め、トレイの状態を「要確認」にする
- 要求するスコープは `https://www.googleapis.com/auth/gmail.readonly` のみ
- このリポジトリに認証情報は含まれない。`.gitignore` でも除外している
- サービスアカウント鍵はドメイン全体のメールを読める。アプリ側のアカウント制限は設定にすぎず、鍵そのものの権限は制限されない。取り扱いには相応の注意が要る

MIT ライセンスの定めるとおり、本ソフトウェアは現状有姿で提供され、いかなる保証もない。特に次の点に注意すること。

- 添付ファイルの取りこぼしや保存失敗が起こり得る。**業務上の記録を保全する唯一の手段として使わないこと**

## 開発

アプリ本体の Python ファイルは `app\`、切り分け用のバッチと保守用のスクリプトは `tools\` にある。`requirements.txt` は `requirements.lock` を作り直すときの元の一覧で、作り直す手順は SETUP_GUIDE.md の「依存パッケージ」にある。テストはリポジトリのルートで実行する。

```
python -m unittest discover -s tests -t . -v
```

Gmail API へは接続せず、ページネーション・カーソル・重複排除・クラッシュ復旧・保持期間などを検証する。
