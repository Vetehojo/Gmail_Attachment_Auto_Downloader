# Gmail Attachment Downloader

Gmail に届いた添付ファイルを、Windows PC の指定フォルダー（ファイルサーバーや NAS 上の共有フォルダーを含む）へ自動保存する常駐ツール。

> **English**: A Windows tray application that automatically downloads Gmail attachments into a local or network folder. Read-only Gmail access, durable SQLite queue, Japanese UI. MIT licensed and provided as-is.

## できること

- 一定間隔で Gmail を確認し、新着メールの添付ファイルを保存先へダウンロードする
- 保存名を「元ファイル名 / 受信日 / 件名 / 送信元」のテンプレートで整形する
- 取得状況を SQLite の永続キューで管理する。PC を落としても、同じ添付を二重に保存したり取りこぼしたりしない
- 失敗した添付はタスクトレイのアイコンで警告し、一覧から内容を確認して再取得できる
- 保存先ごとにアカウントを分けられる（Google Workspace のドメイン全体の委任を使う場合）

## できないこと

- **メール本文中の URL は扱わない。** 添付ファイルだけが対象
- Gmail 以外のメールサービスには対応しない
- 保存先は Windows から見えるフォルダーのみ。クラウドストレージへ API で直接アップロードはしない
- **メールボックスへの書き込みを一切しない。** 送信・削除・既読化・ラベル変更はできない（`gmail.readonly` のみを使う）

## 動作環境

- Windows 10 / 11
- Python 3.14 専用。3.13 以下・3.15 以上は対応せず、setup.bat が停止する
- Gmail API を有効化した Google Cloud プロジェクト（利用者自身が用意する）

## 導入

### 1. Google 側の準備

自分の Google Cloud プロジェクトを作成し、Gmail API を有効化して、認証方式に応じた JSON を用意する。

| 使い方 | 必要なもの |
| --- | --- |
| 個人 Gmail / 単独アカウント | デスクトップアプリ用の OAuth クライアント JSON |
| Google Workspace の複数アカウント | サービスアカウント JSON ＋ 管理コンソールでのドメイン全体の委任（`gmail.readonly` のみ承認） |

OAuth 同意画面を「本番環境」にしていない場合、リフレッシュトークンが 7 日で失効する。継続運用するなら公開ステータスを本番にすること。未検証のアプリでは同意時に「Google で確認されていません」の警告が出るが、自分のプロジェクトで自分のメールボックスを読む用途ではそのまま進めてよい。

### 2. インストールと設定

```
setup.bat
```

Python と依存パッケージを確認・導入したあと、設定画面が開く。対象メールアドレス・添付ファイルの保存先・認証用 JSON を指定し、「Googleに接続してテスト」で導通を確認する。テストでは設定も認証情報も書き換えない。「保存」を押したときに、認証情報（OAuth のログイン結果の `token.json` を含む）と設定をまとめて保存する。

設定を保存すると、お試し取得をするか聞かれる（`[Y/n]`）。お試し取得は、各アカウントの受信トレイから保存対象の添付があるメールを新しい順に 3 件だけ保存する。設定画面の取込期間は使わない。setup.bat は自動取得を開始しない。

### 3. 保存結果の確認

保存先のファイル名と内容を確認する。

お試し取得で保存した添付は、その時点の保存先とファイル名で記録される。あとで保存先やファイル名の設定を変えても、お試し取得をもう一度実行しても、自動取得が始まっても、これらの添付は新しい設定では保存し直されない。必要なら手作業で移動・改名する。トレイメニューの「添付を取り直す」も、最初に記録した保存先へ、現在のファイル名の設定で保存し直すだけである。

認証を済ませたあとや、保存する拡張子を見直したあとなどに、まだ保存していない添付でもう一度試すときは `trial_download.bat` を実行する。トレイアプリが動いているとお試し取得は実行できないので、先にトレイメニューの「終了（自動取得を停止）」で終了しておく。

### 4. 自動取得の開始

```
register_logon_task.bat
```

ログオン時にトレイアプリを起動し、5 分ごとに監視プロセスの生存を確認するタスクを登録する。登録が終わると、登録したタスクを実行してその場でトレイアプリを起動する。一時停止中や設定が未完了でなければ、そのまま自動取得が始まる。起動できなかった場合は次回ログオン時に起動する。お試し取得で保存した添付は、自動取得でも同じ添付として扱い、重複して保存しない（確認方法は SETUP_GUIDE.md の「お試し取得」を参照）。

詳しい手順・仕様は [SETUP_GUIDE.md](SETUP_GUIDE.md) を参照。

## タスクトレイのメニュー

| 項目 | 内容 |
| --- | --- |
| 状態を表示 | 接続方式・状態・未処理件数・直近のエラーを確認する |
| 今すぐGmailを確認 | 次の定期確認を待たずに実行する |
| 一時停止 / 再開 | 自動取得を止める・再開する |
| 失敗した添付 | 失敗した添付の内容を確認し、再取得・無視ができる |
| 添付を取り直す | 直近 90 日以内に取得できた添付を、最初に保存した保存先へもう一度ダウンロードする |
| 期間を指定して再確認 | 指定した日以降のメールを確認し直す |
| 設定 | 設定画面を開く |
| 添付ファイルの保存先を開く | 保存先フォルダーをエクスプローラーで開く |

## 認証情報の扱い

- 指定した JSON と、OAuth 認証後の `token.json` は、設定画面で「保存」を押したときに `%LOCALAPPDATA%\GmailAutoDownloader\` へ保存し、Windows ACL の継承を切って実行ユーザーだけがアクセスできるようにする
- 接続テストで確認したメールボックスを記録し、自動取得は実際に接続したメールボックスが記録と違えば取得を止め、トレイの状態を「要確認」にする
- 要求するスコープは `https://www.googleapis.com/auth/gmail.readonly` のみ
- このリポジトリに認証情報は含まれない。`.gitignore` でも除外している
- サービスアカウント鍵はドメイン全体のメールを読める。アプリ側のアカウント制限は設定にすぎず、鍵そのものの権限は制限されない。取り扱いには相応の注意が要る

## 無保証について

MIT ライセンスの定めるとおり、本ソフトウェアは現状有姿で提供され、いかなる保証もない。特に次の点に注意すること。

- Google の API 仕様・認証方式・検証ポリシーの変更により、予告なく動作しなくなる可能性がある
- 添付ファイルの取りこぼしや保存失敗が起こり得る。**業務上の記録を保全する唯一の手段として使わないこと**
- 保存先の空き容量・アクセス権・ウイルス対策製品の影響は利用者の責任範囲

## 開発

アプリ本体の Python ファイルは `app\`、切り分け用のバッチは `tools\` にある。テストはリポジトリのルートで実行する。

```
python -m unittest discover -s tests -t . -v
```

Gmail API へは接続せず、ページネーション・カーソル・重複排除・クラッシュ復旧・保持期間などを検証する。
